3. SEC-AUTH-02 FIX: COMPLETE LOGOUT TOKEN EXTRACTION & REVOCATION
--------------------------------------------------------------------------------
Vulnerability:
Previously, /api/v1/auth/logout inspected only request.cookies.get(ACCESS_COOKIE).
Bearer-only clients calling /logout were returned 204 No Content without setting
UserSession.revoked_at, leaving the token live for up to 30 minutes.

Resolution (backend/app/routers/auth.py):
1. Reused _extract_token(request) helper matching get_current_user (cookie, else Bearer).
2. If token is missing, returns HTTP 401 Unauthorized ("Not authenticated").
3. If token is invalid or expired, returns HTTP 401 Unauthorized ("Invalid or expired token").
4. Decodes jti and sets UserSession.revoked_at = datetime.now(timezone.utc) in PostgreSQL.
5. Deletes auth cookies and returns HTTP 204 No Content.

Empirical Test Output:
- Unauthenticated logout (no cookie, no header): HTTP 401 Unauthorized -> {"detail": "Not authenticated"}
- Cookie logout: HTTP 204 No Content -> DB revoked_at IS NOT NULL
  Replay via Cookie: HTTP 401 Unauthorized -> {"detail": "Session revoked or not found"}
  Replay via Bearer: HTTP 401 Unauthorized -> {"detail": "Session revoked or not found"}
- Bearer logout: HTTP 204 No Content -> DB revoked_at IS NOT NULL
  Replay via Bearer: HTTP 401 Unauthorized -> {"detail": "Session revoked or not found"}
  Replay via Cookie: HTTP 401 Unauthorized -> {"detail": "Session revoked or not found"}

Mutation Check:
When _extract_token is mutated to inspect only cookies (reverting to buggy behavior):
- test_bearer_logout_revokes_session_and_blocks_replay FAILS (100% caught: bearer logout returns 401, or fails to revoke).
- test_unauthenticated_logout_returns_401 FAILS (catches silent 204 bypass).

A. Content-Type: text/plain Probe with JSON Payload and Cookie Auth:
1. POST /api/v1/learn/quizzes/{quiz_id}/submit (declared Pydantic body):
   - Header: Content-Type: text/plain, Origin: http://evil.com
   - Content: {"answers": {"q1": "b"}}
   - Result: HTTP 422 Unprocessable Entity
   - Detail: Input should be a valid dictionary or object to extract fields from
   - Finding: Endpoints with Pydantic request models fail parsing when submitted as text/plain.
     The server does NOT execute the state mutation.
2. POST /api/v1/learn/lessons/{lesson_id}/complete (schema-less endpoint, path parameter only):
   - Header: Content-Type: text/plain, Origin: http://evil.com
   - Result: HTTP 200 OK -> {"xp_awarded": true, "xp_amount": 50, "message": "Lesson complete!"}
   - Finding (Defense-in-depth gap): Endpoints declaring no request body accept text/plain. If a cross-origin
     simple POST without CORS preflight reached the server with cookies attached, the mutation executes.
     Mitigation currently relies entirely on browser SameSite=Lax enforcement.

Formula note:
In grading.py:
_level_threshold(level) = 100 * level * (level - 1) // 2
Level 1: 0..99 XP

The docstring remark "250-499" in legacy code was an informal comment; the executable formula
in Python is 100 * level * (level - 1) // 2. The quadratic formula in SQL is the exact analytic inverse.

B. Advisory Lock Code Placement (backend/app/services/grading.py):
The lock explicitly precedes the count query:
```python
    # Serialize attempt counting per user and quiz using PostgreSQL transaction-level advisory lock
    if db.bind and db.bind.dialect.name == "postgresql":
        # Form stable 64-bit bigint lock key from (user_id, quiz_id)
        lock_key = (hash(user_id) ^ hash(quiz_id)) & 0x7FFFFFFFFFFFFFFF
        await db.execute(select(func.pg_advisory_xact_lock(lock_key)))

    # Count previous attempts
    attempt_count_result = await db.execute(
        select(func.count()).where(QuizAttempt.user_id == user_id, QuizAttempt.quiz_id == quiz_id)
    )
    attempt_count = attempt_count_result.scalar_one()

    if attempt_count >= quiz.max_attempts:
        raise MaxAttemptsExceededError(
            f"Maximum attempts ({quiz.max_attempts}) reached for this quiz."
        )
```
